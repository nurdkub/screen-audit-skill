# Шкала screen-audit: как проверять каждый пункт

Источники правил: `docs/screen.md` (слои, поля, ритм, текстовые стили), `docs/principles.md`
(сквозные правила, дефолты сборки), `docs/tokens.md` (айдентика). Здесь — только как пункт
проверить и где обычно ломается. Спорное решается по источнику, а не по этому файлу.

## Гейт ДС

Проверяется кодом, без скриншота. Каждое нарушение — блокер с `файл:строка`.

| Что ищем | Нарушение |
|---|---|
| Цвет литералом или из `palette` / `colorScheme` | токен ниже mapped или hex |
| Отступ числом вне шкалы | «новое значение отступа» |
| Свой `button`, карточка-компонент, модалка, SVG-иконка | чужой примитив вместо Square |
| Скругление, тень в разметке экрана | айдентика: углы прямые, тень только у накладок компонента |
| Класс иконок руками, `Icon` с размером внутри слота | правило 5 `CLAUDE.md` |
| Нет продуктовой темы | экран в чужой теме |

Расхождения шаблона продукта (`@/shared/business`, `@/shared/platform`) гейт не трогает.

## ИИ-паттерны

Проверяется кодом, потом глазами на скриншоте. Почему их ловим отдельно: каждый собирается
из законных токенов (рамка `border/success/default` толщиной `borderWidth/4` — законна), и гейт
ДС проходит. Признак общий — элемент украшает, а не сообщает.

| Паттерн | Как выглядит в коде | Замена |
|---|---|---|
| Полоса сбоку | рамка только с одной стороны, цветная или толще `borderWidth/default` | знак `StatusIcon`, подложка состояния, `Badge` |
| Моноширинный | моноширинная гарнитура, группа `description` | `body/m`, `body/s` |
| Капс | преобразование в прописные, разрядка | `body/s` + `text/neutral/secondary` |
| Надзаголовок | короткая подпись строкой **над** `headline/*` | убрать или перенести под заголовок |
| Иконка в подложке | `Icon` внутри блока с фоном и размерами | `Icon` без подложки |
| Точка-статус | пустой блок 6–10 px с фоном состояния | `Badge`, `TableRowStatus` |
| Градиент | `linear-gradient`, `bg-gradient-*` | плоский токен |
| Эмодзи | символ эмодзи в JSX | `Icon` |
| Курсив | `italic`, `<em>`, `<i>` | вес `Strong` или цвет текста |

Исключения: хром полигона, блок кода, нейтральная линия 1px как граница участка внутри
плоскости, рамка `Blackout`/накладки, которую приносит компонент.

## 1. Прищур

**Что проверяем:** у экрана есть один главный элемент, и он побеждает размытием.

**Как:** скриншот с размытием 4–6 px. Назвать вслух, что видно первым. Если первым видна
кнопка в шапке, а главное — метрика под ней, — «нет».

**Ловушки:**
- Главное «побеждает» громкостью: `h3` на числе рядом с `h3` страницы, primary-кнопка
  рядом с красной карточкой. Чинится тишиной соседей, а не новым стилем главного.
- На экране без главного (список настроек) пункт выполнен, если читается заголовок
  страницы, затем заголовки блоков, — ровная лестница и есть ответ.

## 2. Серый

**Что проверяем:** иерархия держится без цвета, цвет говорит только о состоянии.

**Как:** скриншот с `grayscale(1)`. Если главное перестало отличаться от соседей — цвет
работал вместо иерархии.

**Ловушки:**
- Акцентная подложка (`surface/accent/*`) как способ «выделить блок» без состояния.
- Цветной текст ссылки как единственный признак главного действия.

## 3. Слои

**Что проверяем:** три слоя и только они.

| Где | Должно быть |
|---|---|
| Под всем | `background/neutral/subtle-1`, ставится один раз на странице |
| Карточка на фоне | белая, **без** рамки |
| Плоскость внутри карточки, накладка | серая или подкрашенная заливка, рамка `border/neutral/tertiaryDefault` |
| Колонка меню, колонка контента | своего фона нет, разделены линией |

**Ловушки:** рамка «для аккуратности» у каждой карточки; белая плитка внутри белой
карточки (вложенность стёрта); `Divider` между карточками — он живёт только внутри блока.

## 4. Шов и поле

**Что проверяем:** `gap/04` — только шов между плоскостями, поля по уровню.

**Как:** найти все места, где стоит `gap/04`. Для каждого — тест из `screen.md`: мысленно
снять с соседей заливку. Зазор перестал что-то разделять — это не шов.

| Что | Должно быть |
|---|---|
| Карточка ↔ карточка, плитка ↔ плитка, кнопка ↔ кнопка | `gap/04` |
| Поле карточки на фоне | `paddings/08`, все стороны |
| Поле вложенной плоскости | `paddings/07` |
| Колонка контента и меню | `paddings/08` по бокам; под `ActionBar` — только по бокам |

**Ловушка:** `gap/04` между иконкой и текстом в разметке экрана. Внутри `Button` и `Link`
это метрика компонента и законна; в разметке экрана — почти всегда ошибка.

## 5. Ритм внутри плоскости

**Что проверяем:** ступень по родству, шаг между уровнями, потолок.

| Что рядом | Ступень |
|---|---|
| Иконка и текст одной надписи | `gap/02` |
| Заголовок и подпись под ним | `gap/03` |
| Строки списка, ряд бейджей | `gap/05` |
| Части плитки; аватар и описание | `gap/06` |
| Крупные части карточки | `gap/07` |
| Заголовок блока и содержимое | `gap/08` |
| Знак статуса и текст | `gap/05`, знак 16 |

**Список читается списком — проверка глазами.** На скриншоте найти каждый список (задачи,
факты, комментарии) и спросить: видно ли с первого взгляда, где начинается пункт, без чтения
текста? Многострочные пункты с разницей зазоров в одну ступень (4 и 8) на глаз сливаются
в абзац, даже когда по лестнице всё верно. Чинится маркером из Square, а не воздухом:

| Что за список | Маркер |
|---|---|
| Задачи, которые человек выполняет | `Checkbox` — пункт и обещание действия сразу |
| Строки с несколькими полями | `Table` |
| Участки разного смысла | `Divider` между ними |
| Однострочные факты | зазор по лестнице, маркер не нужен |

Ловушка, на которой скилл споткнулся 19.10.2026: пункт 11 «Вычитание» снял с задач всё
«лишнее», и вместе с украшениями ушёл маркер. Маркер списка — не украшение.

**«Нет», если:** две соседние группы разных уровней стоят на одной ступени (группировка
не читается); зазор внутри больше поля (`gap/09+`) без разгона высоты карточки в сетке;
внутри плоскости встречается `gap/04`.

## 6. Лестница стилей

**Продукт:** страница `headline/h3`, блок `h4`, содержимое блока `h6` (допустим `h5`),
основной текст `body/m`, необязательный `body/s`, `body/l` — только промо-модалка.
`h1`, `h2`, группа `description` — никогда.

**Сайт:** hero `h1`, блок `h2`, подблок `h4`, карточка `h5`, содержимое `h6`, текст `body/l`.

**«Нет», если:** колонки смешаны (сайтовый `h2` в продукте); стиль выбран по размеру,
а не по роли (`h4` на подписи, потому что «покрупнее»); основной текст набран `body/s`.

**Не провал:** продукту нечем выделить число — `h3` на числе по README прототипа. Пункт
выполнен, в отчёт идёт раздел «В ДС».

## 7. Подписи тише значений

**Что проверяем:** вспомогательное (подпись поля, заголовок столбца, дата, автор, счётчик)
опущено относительно данных.

**Рычаги Square по порядку:** цвет текста `text/neutral/secondary` → `text/neutral/tertiary`
→ ступень `body/s`. Достаточно одного рычага; подпись и цветом, и ступенью, и весом
сразу — это уже третий план, а не второй.

**Не берётся:** капс-подпись мелким кеглем (совет refactoring-ui) — такого стиля в ДС нет;
`text/neutral/quaternary` для текста, который надо прочитать.

## 8. Один акцент

**Что проверяем:** в каждой зоне (шапка страницы, карточка, модалка) одно главное действие
и один акцент.

**«Нет», если:** две `priority="primary"` в одной зоне; primary-кнопка вторичного действия
(«Выгрузить отчёт») спорит с главным элементом экрана; несколько цветных подложек
без состояния.

## 9. Ширина

**Что проверяем:** абзац `body/m` не тянется на всю колонку 1100+ px, поля формы не растянуты
на всю ширину карточки.

**Ориентир:** 45–75 знаков на строку текста, 300–500 px для поля формы. Канонических ширин
колонки в ДС нет (открытый вопрос `screen.md`), поэтому ограничение в прототипе — его
решение, и оно называется в отчёте одной строкой.

**Заодно:** экран на 1100–1280 не уезжает вбок, колонки сжимаются, а не наезжают.

## 10. Роль токена цвета

**Что проверяем:** не сам цвет, а выбор ступени. Значения и контраст токенов выверила ДС,
им доверяем; ошибиться можно только ролью.

| Где | Роль |
|---|---|
| Текст, который читают обязательно: название, значение, пункт списка | `text/neutral/primary` |
| Подпись, метаданные, пояснение под значением | `text/neutral/secondary` |
| Третий план: счётчик, служебная дата, плейсхолдер | `text/neutral/tertiary` |
| Состояние: ошибка, успех, предупреждение | `text/error/*`, `text/success/*`, `text/warning/*` — только у состояния |
| Плоскость на фоне страницы | `surface/onColor/neutral/primary` |
| Вложенная плоскость | `background/neutral/subtle-1`, `surface/accent/tertiary` |
| Карточка в состоянии | `surface/<состояние>/secondary` |

**«Нет», если:** пояснение набрано `primary` и спорит со значением; важный текст ушёл
в `tertiary`; цвет ошибки стоит у того, что ошибкой не является (красный заголовок «для
акцента»); две соседние подписи одной роли набраны разными ступенями.

**Тема по логотипу** — в гейте, не здесь: логотип d8n — `platform`, Documentolog — `business`.

## 11. Вычитание

**Что проверяем:** у каждого элемента есть работа.

**Как:** пройти экран сверху вниз и про каждый блок, строку, иконку, подпись спросить:
что потеряет пользователь, если это убрать? Нет ответа — «нет» по пункту.

**Типовые находки:**
- плоскость, в которой нет ни данных, ни действия: «Нет новых комментариев» отдельной
  карточкой;
- подзаголовок страницы, который ничего не добавляет к заголовку;
- подпись-пояснение к очевидному («Здесь появятся ваши документы» под пустым списком
  документов);
- счётчик, который никто не считает.

**Не путать с пустым состоянием по делу:** если пустой блок — то место, куда пользователь
придёт за данными, он остаётся, но одной строкой, а не карточкой с иконкой и абзацем.

## 12. Без дублей

**Что проверяем:** каждый факт стоит в одном месте.

**«Нет», если:**
- число в метрике повторяет число строк в списке рядом, и они не связаны действием;
- один и тот же список в двух видах (задачи справа повторяют строки таблицы);
- подзаголовок пересказывает заголовок, подсказка под полем — его подпись;
- одно действие на экране дважды (кнопка в шапке и такая же в блоке).

**Какое место оставить:** то, где с фактом можно действовать, — строку, по которой
переходят, кнопку рядом с данными.

## 13. Бюджет оформления

**Что проверяем:** плоскость не пёстрая.

**Как:** для каждой плоскости выписать разные текстовые стили (`h4`, `body/m`,
`body/mStrong`, `body/s` — каждый отдельно) и разные цвета текста. Цвет состояния
(`text/error/*`, `text/success/*`) в бюджет не входит: он сообщает, а не оформляет.

| | Бюджет |
|---|---|
| Текстовые стили в плоскости | не больше 3 |
| Цвета текста в плоскости | не больше 2 (`primary` и `secondary`, или `primary` и `tertiary`) |

Стили внутри компонентов (`Table`, `Checkbox`, `Badge`) не считаются: их выбирает ДС.

## 14. Иконки по делу

**Что проверяем:** иконка помогает узнать, а не украшает.

| Иконка по делу | Иконка-украшение |
|---|---|
| в кнопке действия, где без подписи (`IconButton`) или с ней узнаётся быстрее | у каждого заголовка блока |
| тип файла, статус, пункт меню | рядом с каждой подписью в списке фактов |
| знак статуса у итога (`StatusIcon` 16) | крупная иконка над пустым состоянием блока |

**Как:** посчитать иконки вне компонентов-кнопок и меню. Если иконка стоит у каждого
элемента одного ряда, она перестала различать — это украшение.

## Привязка к стеку полигона

_Всё выше — именами токенов Figma. Здесь — как то же проверить на полигоне
(Vite + Tailwind + CSS-переменные)._

**Грепы гейта** (по папке прототипа):

```bash
grep -nE "#[0-9a-fA-F]{3,8}\b" src/prototypes/<слаг>/*.tsx
grep -nE "\-\-(palette|colorScheme|primitives)-" src/prototypes/<слаг>/*.tsx
grep -nE "\b(rounded|shadow)(-[a-z0-9]+)?\b|border-radius|box-shadow" src/prototypes/<слаг>/*.tsx
grep -nE "\[[0-9]+px\]|: ?'?[0-9]+px" src/prototypes/<слаг>/*.tsx
grep -nE "<svg|className=\"[^\"]*material-icons" src/prototypes/<слаг>/*.tsx
grep -n "dataset.product" src/prototypes/<слаг>/index.tsx
```

Тему `platform` ставит и шаблон `PlatformShell` из `@/shared/platform` — экран на нём
своего `dataset.product` не держит, и это не нарушение. Числа в `px` бывают законны (ширина колонки, размер мокапа) — каждое смотреть глазами.

**ИИ-паттерны грепом** (каждое совпадение смотреть: хром на `zinc` и блоки кода — не нарушение):

```bash
P=src/prototypes/<слаг>
grep -nE "borderInline(Start|End)|border(Left|Right):|\bborder-[lrse]-[0-9a-z]" $P/*.tsx   # полоса сбоку
grep -nE "font-mono|monospace|description-" $P/*.tsx                                     # моноширинный
grep -nE "\buppercase\b|textTransform|tracking-|letterSpacing" $P/*.tsx                  # капс, разрядка
grep -nE "gradient" $P/*.tsx                                                              # градиент
grep -nE "\bitalic\b|fontStyle|<em>|<i>" $P/*.tsx                                         # курсив
grep -nP "[\x{1F300}-\x{1FAFF}\x{2600}-\x{27BF}]" $P/*.tsx $P/*.ts                       # эмодзи
grep -nE "(rounded-full|borderRadius: ?'50%').*(size|inlineSize|w-)" $P/*.tsx              # точка, кружок
```

Верхние и нижние линии (`borderBlockStart` / `borderBlockEnd`) не ищутся: это разделители строк
и участков, а не украшение. Градиент в `maskImage` — затухание края прокрутки, не нарушение.
Надзаголовок и иконку в подложке грепом не поймать — только глазами на скриншоте.

**Пункт 4 и 5 грепом:** `items-center gap-04` почти всегда ошибка; `gap-09`, `gap-10`,
`gap-11` внутри карточки — проверить, разгон ли это высоты в сетке.

```bash
grep -nE "gap-04|--gap-04" src/prototypes/<слаг>/*.tsx
grep -nE "gap-(09|1[0-3])|--gap-(09|1[0-3])" src/prototypes/<слаг>/*.tsx
```

**Пункт 6 грепом:** классы стилей названы как в Figma — `headline-h3`, `body-m`, `body-sStrong`.

```bash
grep -nE "headline-h[12]\b|description-" src/prototypes/<слаг>/*.tsx
```

**Тест прищура и серого** — в браузерной панели дев-сервера (`preview_start`), через
`javascript_tool`, затем скриншот, затем сброс:

```js
document.documentElement.style.filter = 'blur(5px)'      // пункт 1
document.documentElement.style.filter = 'grayscale(1)'   // пункт 2
document.documentElement.style.filter = ''               // вернуть
```

Фильтр на `<html>` не трогает `data-product`, тема остаётся. Перед замерами цветов через
`getComputedStyle` в скрытой панели глушить переходы (`* { transition: none }`) — иначе
рамка читается начальным цветом (подводный камень из `CLAUDE.md`).

**Тема (гейт)** — `document.documentElement.dataset.product` в `javascript_tool` и логотип
на скриншоте. `platform` у экрана d8n ставит `PlatformShell`, своего атрибута прототипу
не нужно; у экрана Business атрибута нет вовсе.

**Ширина (пункт 9)** — в прототипе ограничивается утилитой Tailwind (`max-w-prose`,
`max-w-xl`): токена ширины в ДС нет.
